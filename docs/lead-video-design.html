Design · Agent lead chat

One click, one property, one video

The agent picks a property the buyer is interested in and clicks Generate. ACOT collects the photos and facts itself, Luma turns the real photos into moving shots, and the finished video goes into the chat.

Updated 26 Nov 2026Repos: Acot-AI-, ACOT-BACKEND, acout-frontendStatus: building

The idea

Agents today keep brochures, amenity sheets and photos in their own drive and send them file by file. The buyer has to open each one. Instead, the agent clicks once and the buyer gets one short vertical video in the chat.

Decided: the agent uploads nothing and fills nothing in. All data is collected automatically. Luma is the video engine.

One-click flow

Agent chat → + → Create property video
  Pick one of the buyer's searched properties → Generate
  1. Collect     ACOT catalog: project, photos, latest sale and rent, handover
                 later: developer's official page for extra photos and amenities
  2. Script      fixed template from those facts; Google voice
  3. Luma        each real photo → a 5 s moving shot (in parallel, cached)
  4. Assemble    FFmpeg: Luma shots + voice + captions + logo → 9:16 MP4
  5. Share       agent previews → Send to buyer → plays in the chat

If Luma fails or is switched off for a shot, that shot falls back to the existing slow-zoom photo, so the video still finishes. A property with too little data shows "Not enough data for this property yet" instead of a weak video.

How it works

  1. The message body is text with a video link, like property cards and meetings already are. No chat schema change.
  2. The link is signed by the backend, so the buyer can play it without the agent's login, and nobody can guess other video links.
  3. Voice is baked into the MP4, so preview, download and chat all play the same file.

Later

Chapter shortcuts (Photos, Market, Handover) and buttons (Book a viewing, Ask a question) under the player.

Facts shown or spoken in the video always come from data, never from the video model.

How Luma is used

  • Image to video only. Each shot starts from a real photo, with a prompt to keep the building, layout and materials unchanged and add no people or text. Luma never invents a scene from text, so the video can't show a pool or view the property doesn't have.
  • Parallel. Up to 4 shots are requested at once, so the wait is about one Luma generation, not one per photo.
  • Cached per photo. A finished shot is kept on disk, keyed by the photo. The next agent who generates the same property pays nothing for Luma and waits only for voice and assembly.
  • Capped. At most 8 Luma shots per video (setting VIDEO_LUMA_MAX_SHOTS).
  • Switch. On when LUMA_AGENTS_API_KEY is set; VIDEO_LUMA_ENABLED=false turns it off.

Build order
